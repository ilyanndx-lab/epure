# Régénéré le 2026-08-10 (deuxième build de la journée) : `google-generativeai`
# est passé de `requirements.txt` à `HORS_PAQUET_PIP`, et son retrait fait

# bien qu'absents du paquet livré : chromadb les déclare en dépendances
# directes et inconditionnelles, donc `pip` les installe quand même pour le
# satisfaire — ils sont purgés APRÈS coup (`PURGE_DISTRIBUTIONS`), lecture du
# `RECORD` de leur `.dist-info` puisqu'aucun des deux ne s'installe comme un
# simple dossier `site-packages/<nom>/`. Un `sitecustomize.py` posé dans le
# paquet stub l'unique import que leur absence casserait

# retirer `sitecustomize.py` fait effectivement casser `import chromadb`.
#
# Pourquoi ce fichier existe : `backend/requirements.txt` épingle les paquets
# directs, mais son résolveur reste libre sur l'arbre transitif. Mesuré :
# installer `google-generativeai==0.8.6` rétrograde `protobuf` 7.35.1 → 5.29.6
# et fait reculer le résolveur d'une quinzaine de versions de
# `grpcio-status` — rien ne casse (22 imports sur 22 passent), mais deux
# constructions à deux dates ne donnent pas le même paquet. `pip install -c
# tools/contraintes-paquet.txt` fige l'arbre entier au lieu de le laisser
# dériver avec ce qui est publié sur PyPI entre deux builds.
#
# `pip`, `setuptools`, `kubernetes`, `grpcio`, `opentelemetry-exporter-otlp-
# proto-grpc` et `googleapis-common-protos` apparaissent alors qu'ils sont
# retirés du paquet après coup (`PURGE_SITE_PACKAGES` / `PURGE_DISTRIBUTIONS`) :
# ce fichier fixe ce qui a été INSTALLÉ, la purge reste une étape séparée.
#
