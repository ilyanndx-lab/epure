# Contraintes de reproductibilité pour tools/faire_paquet.py.
#
# `pip freeze` du site-packages Python 3.12 embeddable qui a produit et vérifié
# le paquet du 2026-08-13 (132,2 Mo zippé). Généré, pas écrit à la main : ne pas
# éditer une ligne isolément.
#
# ⚠️ CE FICHIER EST EN RETARD DE DEUX LOTS, et c'est sans effet en attendant.
# Il ne connaît ni `python-pptx`/`openpyxl` (lecture des documents, 2026-08-24),
# ni la sortie de `pip`/`setuptools` de la purge (2026-08-23). Un fichier de
# contraintes n'INSTALLE rien : il n'épingle que ce qu'il liste, donc ces paquets
# se résolvent librement et le build passe. Les ajouter à la main donnerait un
# fichier décrivant un environnement que personne n'a installé — ce que
# l'avertissement ci-dessus interdit précisément. Il se régénère en construisant
# un paquet avec `--sans-contraintes` puis en lisant `python.gel` du `PAQUET.json`
# produit. Le poids annoncé (132,2 Mo) est lui aussi périmé : +15,2 Mo de pip et
# setuptools, +6,6 Mo de lecteurs, soit ≈ 154 Mo — arithmétique, pas mesure.
#
# Régénéré le 2026-08-13 après le retrait de `chromadb`
# (`docs/remplacement-vectoriel.md`, étape D). **53 paquets contre 101** dans la
# version précédente : 49 partis, aucun arrivé — c'est la moitié de l'arbre
# transitif qui disparaît avec UNE seule dépendance directe, ce qui dit assez
# quelle place `chromadb` tenait pour ce qu'on lui demandait. Outre lui-même :
# `grpcio`, `kubernetes`, `googleapis-common-protos`, les six `opentelemetry-*`,
# `pypika`, `mmh3`, `bcrypt`, `orjson`, `overrides`, `pybase64`, `tenacity`,
# `typer`/`rich`/`pygments`/`markdown-it-py`/`mdurl`/`shellingham` (son interface
# en ligne de commande), `jsonschema` et sa grappe, `aiohttp` et la sienne,
# `requests`/`urllib3`/`oauthlib` (tirés par `kubernetes`), `websockets`,
# `watchfiles`, `build`/`pyproject_hooks`.
#
# ⚠️ `websockets` était dans ces 49 départs et n'aurait pas dû l'être : c'était la
# seule implémentation WebSocket de l'arbre, arrivée par l'`uvicorn[standard]` que
# `chromadb` déclarait. Son départ a coûté tout `/ws/*` chez un destinataire
# (« No supported WebSocket library detected » au démarrage, puis 401 sur
# /ws/chat, la requête d'upgrade étant retombée en GET HTTP). Remplacée le
# 2026-08-23 par `wsproto`, déclarée directement dans `backend/requirements.txt`
# — Python pur, donc pas de wheel d'architecture à vérifier, et pas un seul
# transitif nouveau puisque `h11` est déjà là. `wsproto` est donc le 53e paquet
# ci-dessous, ajouté à la main plutôt que par régénération : le reste de la liste
# est bien le `pip freeze` du 2026-08-13.
#
# La leçon est dans ce fichier même : une grappe transitive ne se lit pas comme du
# poids mort du seul fait qu'elle disparaît avec son porteur. `watchfiles` et
# `httptools`, du même extra, l'étaient. Celle-là non, et rien ne les
# distinguait.
#
# Ce que ce fichier ne contient plus non plus, et c'est le vrai changement : la
# distinction entre « installé » et « livré ». Les versions précédentes listaient
# `grpcio`, `opentelemetry-exporter-otlp-proto-grpc`, `googleapis-common-protos`
# et `kubernetes` tout en précisant qu'ils étaient purgés APRÈS installation —
# chromadb les déclarant en dépendances directes et inconditionnelles, `pip` les
# installait quoi qu'on veuille. Ils ne sont plus installés du tout, donc plus
# purgés, donc plus mentionnés. Seuls `pip` et `setuptools` restent purgés (le
# destinataire n'installe rien) et apparaissent encore ci-dessous.
#
# `onnxruntime` reste, et ce n'est pas un résidu : `faster-whisper` et `piper-tts`
# en dépendent tous les deux. `numpy` reste et devient structurel — c'est le
# moteur de calcul de `core/vector_store.py`.
#
# Pourquoi ce fichier existe : `backend/requirements.txt` épingle les paquets
# directs, mais son résolveur reste libre sur l'arbre transitif. `pip install -c
# tools/contraintes-paquet.txt` fige l'arbre entier au lieu de le laisser dériver
# avec ce qui est publié sur PyPI entre deux constructions.
#
# Régénération : reconstruire un paquet avec `--sans-contraintes`, lire
# `python.gel` dans le `PAQUET.json` de l'archive produite, et remplacer ce
# fichier en entier. Vaut la peine quand `backend/requirements.txt` change une
# version directe, ou pour rattraper volontairement des correctifs de sécurité
# transitifs.
